# Phase 2: on-car checklist

HKG Package Manager 1.1.0 adds signed package catalogs on the USB stick, trusted keys, a
green/yellow/red compatibility check before installing, and a desktop mirror CLI. Nothing
here has been tried on the car yet. Design: `docs/superpowers/specs/2026-10-30-hkg-package-manager-design.md`
(Phase 2); catalog format: `docs/catalog/format.md`. Phase 1's checklist
(`docs/testing/2026-10-30-phase-1.md`) still applies for loose zips, queues and restarts.
Please note anything odd, even if it seems small.

Package: `dist/hkg-package-manager.zip` (build: see `README.md`). Use one stick for the
manager if it isn't installed yet, and one test stick at a time (the manager reads one drive
at a time).

## Test catalogs

The catalogs are signed with test-only keys that are public on purpose; never trust them
outside this checklist. Get them either way:

- from the CI artifact `hkg-test-catalogs-<sha or tag>` (it holds `hkg-test-catalogs.zip`;
  unzip it), or
- `python3 tests/catalog/make_catalog.py car dist/test-catalogs` (needs `openssl`; it empties
  `dist/test-catalogs` first).

Either way you get four scenario folders. To use one, copy the **contents** of the folder
(for example `HKGPM/` and `test.a.zip` from `trusted/`) to the root of the test stick, not
the folder itself. Start each scenario from an empty stick (or delete `HKGPM/` first).

| Folder | Holds |
|---|---|
| `trusted/` | `HKGPM/catalogs/cartest/` (catalog "Car test catalog", signed with `test-key.pem`), `HKGPM/keys/test-key.pem` (the public key, for Settings), and a loose `test.a.zip` |
| `tampered-index/` | the same catalog with one byte of `index.json` changed after signing |
| `tampered-zip/` | the same catalog with one byte of `zips/cartest.yellow.zip` changed |
| `unknown-key/` | `HKGPM/catalogs/othertest/` ("Car test catalog (other key)"), signed with `other-test-key.pem` |

Packages in the catalog (each script writes `/data/nemesis/<id>.marker` and exits 0, except
`cartest.restart`):

| Package | Name | Compatibility | Expected colour |
|---|---|---|---|
| `cartest.green` | Car test green | works on build `NEEV23.*` | green on this car (`NEEV23.USA.`) |
| `cartest.wifi` | Car test wifi | works on hardware `wifi` | green on a car with Wi-Fi |
| `cartest.yellow` | Car test yellow | none | yellow |
| `cartest.red` | Car test red | not on build `*` | red |
| `cartest.conflict` | Car test conflict | conflicts with `test.a` | red while `test.a` is installed, otherwise yellow |
| `cartest.restart` | Car test restart | works on build `*`; script is `echo "cartest.restart: restarting"` then `exec /system/bin/reboot` | green |

`test.a.zip` is the same as Phase 1's: id `test.a`, name `Test A`, version `1.0.0`,
postinstall writes `/data/nemesis/test.a.marker`.

The manager's verdict lines are: green "Works on this car"; yellow "No compatibility
information" (no data), "Not listed for this car" (data, no match) or "Not from a catalog"
(loose zips); red "Marked as not working on this car" or "Conflicts with installed <ids>".

## Steps

1. **Install 1.1.0.** Put `dist/hkg-package-manager.zip`'s contents on a stick and plug it
   in (or do step 11 to update from 1.0.x). Open the manager > Settings: "Catalog keys" lists
   "No trusted keys." and offers "Add keys from the USB drive".
2. **Trusted catalog, trust from the drive screen.** Copy `trusted/`'s contents to the test
   stick, plug it in and open the "USB drive" tab. Expected: the line "Untrusted catalog
   Car test catalog, key fingerprint " followed by 64 hex characters in groups of four, and a
   "Trust this key" button; no packages are listed under it. A "Not from a catalog" header
   lists `Test A` (id `test.a`, `New`) with the yellow "Not from a catalog". Tap "Trust this key": the dialog reads
   "Trust catalogs signed with this key?", then the name, the fingerprint and "Check the
   fingerprint with the catalog's publisher first." Compare the fingerprint with the one the
   catalog's index shows in `HKGPM/catalogs/cartest/index.json` (field `key`, the same
   64 characters without spaces). Confirm with "Trust this key". Expected: a bold "Car test
   catalog", grey "hkg-package-manager tests" and six rows.
3. **Colours and single installs.** On the trusted catalog (do not install `test.a` yet):
   - `Car test green` (`cartest.green   1.0.0`): green "Works on this car". Install: it
     asks "Install Car test green 1.0.0?" with no extra warning line. Expected afterwards:
     "Installed" and `/data/nemesis/cartest.green.marker`.
   - `Car test wifi`: green "Works on this car" on a car with Wi-Fi. Install it too.
     On a car where Wi-Fi isn't present it would read yellow "Not listed for this car"; note
     which you see.
   - `Car test yellow`: yellow "No compatibility information". Install asks "Install Car test
     yellow 1.0.0?" followed by "This package hasn't been checked for this car. (No
     compatibility information)". Confirm; it installs.
   - `Car test red`: red "Marked as not working on this car". Install asks "Install Car test
     red 1.0.0?" followed by "This package is marked as not working on this car. (Marked as not
     working on this car)" and a tick "I understand; install it anyway". The Install button in
     the dialog does nothing until the tick is set. Cancel, then once try with the tick: it
     installs.
   - `Car test conflict`: with `test.a` not installed, its verdict is yellow "Not listed for this
     car" (it has compatibility data, but nothing that matches the car).
4. **Conflict turns red.** Install the loose `Test A`. Then the drive screen shows `Car test
   conflict` red "Conflicts with installed test.a", and installing it needs the red tick.
   Uninstall `test.a` in the Installed tab: the row goes back to yellow.
5. **Settings > Add keys and Remove.** Remove the key (Settings > Catalog keys > Remove next
   to the "Car test catalog" entry): the dialog asks "Stop trusting Car test catalog?" with
   Remove and Cancel; confirm: "No trusted keys." Back on the drive tab the catalog is untrusted
   again. In Settings tap "Add keys from the USB drive" (the stick has
   `HKGPM/keys/test-key.pem`): a dialog "Trust catalogs signed with this key?" with the name
   `test-key.pem` and the fingerprint; confirm "Trust this key". Expected: "Added 1 key(s)." and the key listed with its
   fingerprint. Tap it again: "No new keys in HKGPM/keys on the drive." Trusted keys survive
   closing the manager and a head unit restart.
6. **Tampered index.** Replace the stick's contents with `tampered-index/`'s (the key is
   trusted from step 5). Expected: the bold folder name `HKGPM/catalogs/cartest` and, in grey,
   "signature doesn't match: the catalog was changed or damaged". No packages and no Trust button.
7. **Tampered zip.** Use `tampered-zip/`. Expected: `Car test yellow` shows a grey line
   "doesn't match the catalog (size or SHA-256)", no checkbox and no Install button; the other
   five rows are normal. (A zip that is missing from the stick reads "not on this drive"; a zip
   whose id or version differs from its entry reads "zip doesn't match its catalog entry (id or
   version)".)
8. **Unknown key.** Use `unknown-key/` (the other key was never trusted; remove any trust for
   it first). Expected: "Untrusted catalog Car test catalog (other key), key fingerprint "
   and the groups, a "Trust this key" button, and no packages. The fingerprint differs from
   step 2's. Don't trust it, or remove the key again afterwards.
9. **Mixed queue.** Use `trusted/` with the key trusted. Uninstall the test packages from
   the earlier steps in the Installed tab first (or their rows read `Same version`). Tick `Car
   test green` (green), `Car test yellow` (yellow), `Car test red` (red), the loose `Test A`
   (yellow, "Not from a catalog") and `Car test restart` (green), then "Install selected".
   Expected: one confirmation "Install these packages?" with the five lines, then "Not checked
   for this car: " naming the yellows (`Car test yellow` and `Test A`), then "Tick each
   package marked as not working on this car to continue." with one tick for `Car test red`;
   the confirm button stays off until it is ticked. Confirm. The Progress screen opens as in
   Phase 1; the head unit restarts during `cartest.restart`; after it (and NEMESIS's
   question, as in Phase 1 step 4) the manager carries on without installing anything twice.
   Final line: "Finished: 5 installed, 0 failed". Every `/data/nemesis/<id>.marker` exists
   (`cartest.restart` writes none).
10. **Mirror CLI.** On the desktop, run `python3 cli/hkgpm_mirror.py
    dist/test-catalogs/trusted/HKGPM/catalogs/cartest /path/to/emptystick`. The first run prints
    the key's fingerprint and exits 3; check it matches step 2's, then re-run with
    `--fingerprint <64 hex>`. Expected: `HKGPM/catalogs/cartest/` on the stick and nothing
    else. In the car (key trusted), the drive tab lists the same six rows as step 3.
    Try `--only cartest.green`: only that package's zip is on the stick, the index still lists six.
11. **Self-update from 1.0.x.** Start from a car with 1.0.x installed (a v1.0.0 release zip)
    and a non-default opening-button setting (for example Press Navigation). Put
    `packages/hkg.package.manager.zip` from the 1.1.0 `dist/hkg-package-manager.zip` on the test
    stick as a loose zip and tap Update on it: the confirmation reads "Update HKG Package
    Manager 1.1.0?" and ends with "The manager will close while it updates; open it again
    afterwards." Expected: the Installed tab shows 1.1.0 and the opening-button setting
    survived. Then do step 5's Add keys, repeat the update with a rebuilt zip of a higher
    version if you can (`VERSION_NAME=1.1.1 VERSION_CODE=5 tools/build-app.sh`, with
    `version=1.1.1` set in `package/NEMESIS.data` for the build; don't commit it), and check
    the trusted keys are still listed. `/data/nemesis/hkg.package.manager/` must still exist.

## If something goes wrong

- A catalog doesn't show at all: it must be in `HKGPM/catalogs/<id>/` on the stick root and
  the folder name must be the catalog id (`cartest`, `othertest`).
- Colours look wrong for the car: send what Settings and the drive tab show, and the car's
  build id (`getprop ro.build.product` through `nemesis root`).
- Everything else: Settings > "Copy log to USB drive" and send `HKGPM/log.txt` (see Phase 1,
  step 10).

# Phase 1: on-car checklist

HKG Package Manager 1.0.0 installs and uninstalls NEMESIS packages from a USB stick, with an
on-screen app, a queue that survives head unit restarts, and a button that opens it. Nothing
here has been tried on the car yet. Design: `docs/superpowers/specs/2026-10-30-hkg-package-manager-design.md`.

Package: `dist/hkg-package-manager.zip` (build: see `README.md`). Test packages:
`dist/test-packages/` from `tools/build-test-packages.sh`. Please note anything odd, even if it
seems small. Use two sticks if you can: one for the manager, one for the test packages (the
manager reads one drive at a time; with two drives plugged in it asks you to remove the other).

## Step 0: capture the button broadcasts (before installing anything)

The Media button default uses PROVISIONAL broadcast names (core `Button.MEDIA`, a list of
candidates found in the stock framework) until the key-capture kit has run. So step 1's "press
Media three times" may not open the manager yet. This is expected.

1. Run the read-only kit from `dist/hkg-keycap-kit.zip` (build it with `tools/build-kit.sh`;
   `kit/README.txt` says how to run it from NEMESIS Manager's "Run USB NEMESIS.sh").
2. Copy the stick's `KEYCAP/` into `private/KEYCAP/` (never commit it).
3. Fill in `docs/notes/key-capture.md`, and send the `KEYCAP` files so the Button list can be
   corrected (one constant, then a rebuild).

If Media doesn't open the manager in step 1, open it from NEMESIS Manager > Packages > HKG
Package Manager > Launch and carry on; every other step works that way.

## Test packages

Build them with `tools/build-test-packages.sh` (it uses `../hmg_nemesis/Sources/tools/make_nemesis_package.py`
and lints the scripts), or by hand: make a folder per package holding `NEMESIS.data` and
`scripts/`, then `python3 ../hmg_nemesis/Sources/tools/make_nemesis_package.py <folder> -o <name>.zip`.
Each zip has `NEMESIS.data` at its root. Copy the five zips to the root of the test stick (or
into a `packages/` folder on it).

Every script starts with `#!/system/bin/sh` and uses only `echo` and `exit`.

| Zip | `NEMESIS.data` (after `[nemesis]`) | Script |
|---|---|---|
| `test.a.zip` | `id=test.a`, `name=Test A`, `version=1.0.0`, `postinstall=scripts/postinstall.sh` | `echo "test.a" > /data/nemesis/test.a.marker` then `exit 0` |
| `test.b.zip` | `id=test.b`, `name=Test B`, `version=1.0.0`, `postinstall=scripts/postinstall.sh` | `echo "test.b: restarting"` then `exec /system/bin/reboot` |
| `test.c.zip` | `id=test.c`, `name=Test C`, `version=1.0.0`, `postinstall=scripts/postinstall.sh` | `echo "test.c" > /data/nemesis/test.c.marker` then `exit 0` |
| `test.fail.zip` | `id=test.fail`, `name=Test Fail`, `version=1.0.0`, `preinstall=scripts/preinstall.sh` | `echo "test.fail: refusing on purpose"` then `exit 1` |
| `Test Spaces.zip` | `id=test.spaces`, `name=Test Spaces`, `version=1.0.0`, `postinstall=scripts/postinstall.sh` | `echo "test.spaces" > /data/nemesis/test.spaces.marker` then `exit 0` |

## Steps

1. **Install the manager.** Copy the contents of `dist/hkg-package-manager.zip` to a stick root
   (`NEMESIS.data` and `packages/`), plug it in. NEMESIS installs it (it needs the NEMESIS
   command channel; otherwise the install stops with "HKG Package Manager needs NEMESIS with its
   command channel running."). Restart the head unit if NEMESIS says so.
   - Press Media three times: the manager opens (if not, see step 0).
   - Press Navigation three times: NEMESIS Manager opens, and the manager doesn't.
2. **Look at the drive.** Plug in the test stick and open the manager's "USB drive" tab. Expected: five
   rows, each with a status of `New` and an Install button (`Test Spaces` shows with its name
   intact). Nothing says "No USB drive found." or "No zips found on the drive."
3. **Single install of `test.a`.** Tap Install on `test.a`. Expected: the Progress screen shows
   "Installing packages…" with the handler note "If NEMESIS asks to run an item from the USB
   drive, either answer is fine." and "Don't remove the USB drive until the list finishes."
   Answer NEMESIS's question either way. The item ends `installed`, and the finished line reads
   "Finished: 1 installed, 0 failed". The "Installed" tab lists Test A with version 1.0.0, and
   `/data/nemesis/test.a.marker` exists. Back on the drive tab, `test.a` shows `Same version`.
4. **Queue a, b, c.** On the drive tab, tick `test.a` (if step 3 left it as `Same version`, uninstall it first
   in the Installed tab), `test.b` and `test.c` (not `test.fail`), then "Install selected": it asks "Install these
   packages?" with the list; confirm.
   - NEMESIS asks about running an item from the USB drive at the start; either answer is fine.
   - The head unit restarts during `test.b`.
   - After the restart, the manager shows "Unfinished install found: continue?". Answer
     Continue (Yes): the queue carries on with `test.c`.
   - Final report: "Finished: 3 installed, 0 failed".
   - The stick's `NEMESIS.data` is restored to what it was before, or removed if there was none
     (the manager borrows it to feed the queue; `HKGPM/NEMESIS.data.saved` holds the original
     meanwhile).
5. **Queue with `test.fail` in the middle.** Queue `test.a`, `test.fail`, `test.c` (use
   uninstalled ones or reinstall). Expected: `test.fail` ends `failed - install failed: ...`
   (the last line of its output, or `exit <n>`), the other two install, and the final line
   reads "Finished: 2 installed, 1 failed". The queue isn't stopped by the failure.
6. **Pull the stick mid-queue.** Start a queue of `test.a` and `test.c`; take the stick out
   while it runs. Expected: the Progress screen shows "Stopped: <reason>. Plug the drive back
   in to continue." Reinsert it: the prompt "Unfinished install found: continue?" appears.
   Continue: the interrupted item resolves (finished, or marked "interrupted (head unit
   restarted or drive removed)" and retried), and the rest of the queue finishes. Also try
   Discard once: remaining items read "not installed (list discarded)".
7. **Self-update.** On the host, bump the version in both `package/NEMESIS.data` (`version=`)
   and the app: `VERSION_NAME=1.0.1 VERSION_CODE=2 tools/build-app.sh && tools/build-package.sh`
   (don't commit the bump). Put that update zip (the inner `packages/hkg.package.manager.zip`)
   next to `test.c.zip` on the test stick. Queue both. Expected: the manager's update runs last,
   after `test.c`; the head unit restarts it; the report appears after the restart ("Finished:
   2 installed, 0 failed"). The Installed tab shows version 1.0.1.
8. **Uninstall.** In the Installed tab, uninstall `test.a`: result "Uninstalled". Then uninstall
   hkg-climate-page: its result ends with the line "Restart the head unit to finish."
   The locked `usb-handler` row shows no Uninstall button.
9. **Settings.** Open Settings. "Open this app with the car button" offers Media, Navigation
   and Off, with "Presses needed" (default 3). Change the button to Navigation: the note
   "NEMESIS Manager may also open on this button." shows. Restart the head unit: three presses of
   Navigation open the manager (and perhaps NEMESIS Manager too), and the setting survived.
   Self-update again (step 7 with 1.0.2): the setting is still there. Set it back to Media
   afterwards.
10. **Copy log to USB.** In Settings, tap "Copy log to USB drive". Expected: "Log copied to
    <path>" (the drive's `HKGPM/log.txt`). Send that file. In it, find the `StickFs` lines and
    note whether stick writes used the root fallback (writes done through the NEMESIS CLI
    because the app's own write was refused) or went direct.

## If something goes wrong

- The manager won't open with the button: use NEMESIS Manager > Packages > HKG Package Manager
  > Launch, then do step 0 if you haven't, and send `KEYCAP/`.
- "Couldn't read the drive." or "No USB drive found.": replug the stick, with only one drive
  in the car.
- The queue seems stuck, or the head unit restarted and nothing came back: reopen the manager;
  the resume prompt should appear. Copy the log to USB (step 10) and send it.
- A package says `install failed: ...`: that is the last line NEMESIS printed; send the log.
- Uninstalling the manager leaves its settings in `/data/nemesis/hkg.package.manager/` on
  purpose.
